> **Re-gated 2026-09-28; corrected 2026-09-29 — the SPSC port is cancelled, not deferred.** The generational slot map still runs as Phase 1's first deepening: it retires a claim currently **on the resume and not in the code**, so its priority is credibility, not marginal signal. The SPSC port into the Backtester sampler is cancelled outright — a queue has no job there. The Monte Carlo workload is embarrassingly parallel with uniform per-path cost and exactly one output slot per path, so an index-partitioned parallel-for is both correct and faster than a queue: no handoff latency, no contended head/tail cacheline, and no load imbalance for a queue to smooth. Building one to justify a bullet would have produced a design an interviewer dismantles in a single question ("why not a static partition?"). The bullet was corrected instead, and the correct home for SPSC in that repo is streaming ingest — see the row below. The PMR intrusive list stays gated on Phase 4, because it needs the object-lifetime and interposition material taught there; until it lands, the PMR clause stays off the page — **it is currently on the page anyway, in the Orderbook block, and that is a live contradiction** (see the claim audit in [`90-resumes.md`](90-resumes.md)). General rule this establishes: **a bullet whose claim depends on unshipped work does not ship until that work lands.**

Your Orderbook and Backtester are already strong; these are the remaining high-signal additions, gated on the relevant core prerequisite being complete and the current core gate staying green. The cap counts *container rewrites* (the ladder, the slot map, the PMR list — micro-optimizations of the same kind); **infrastructure work does not count against it**, because the ingestion ladder changes what the system *is* rather than how its containers are spelled, and it is the only anchor item that adds a new measurement surface instead of re-measuring an existing one.
